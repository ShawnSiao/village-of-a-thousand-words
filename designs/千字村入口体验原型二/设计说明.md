# 《千字村》入口体验原型二

## 原型定位

这是完整 15 回合最小可行版本的「前五回合验证版」，不是完整游戏，也不再称为完整第一幕。

本原型解决旧版最明显的入口问题：

- 标题页说明《千字村》是什么；
- 明确玩家扮演「守字人」；
- 用序章解释四条世界规则；
- 在获得修改权前阅读 10 段旧碑文；
- 完整展示既有优秀玩法首图；
- 用第一回合逐步教学证词、版本、容量和封存；
- 每回合提供可回溯的「记忆回声」；
- 前五回合总结不再只显示字数，而是说明知识、关系和信仰如何改变。

## 图片原型与前端的关系

本次严格采用「先生成图片原型，再绘制前端」的顺序。

| 图片原型 | 前端落点 |
|---|---|
| `01-标题页图片原型.png` | 标题页全屏视觉，前端叠加标题、介绍、按钮和 15 回合范围 |
| `02-序章图片原型.png` | 三页序章的故事场景与旧纸阅读区 |
| `03-旧碑阅读图片原型.png` | 旧碑阅读的记忆列表、碑面和详情三栏逻辑 |
| `04-玩法教学图片原型.png` | 四步玩法教学完整图片 |
| `05-既有玩法首图.png` | 玩法概览第一屏，以完整可辨认尺寸展示 |

全部会变化的文字、字数、按钮、记忆内容和后果均由前端组件渲染。生成图片不承担动态文字职责。

## 主要流程

> 标题页 → 职责说明或开始 → 三页序章 → 阅读旧碑 → 完整玩法首图 → 四步教学 → 前五回合 → 每回合记忆回声 → 前五回合总结

标题页提供「开始新村志」和「继续旧村志」。存档保存在当前浏览器本地；刷新后返回标题页，可继续到上次状态。

## 核心交互

- 第一回合：完整、预警和英雄三种写法均可直接封存，不修改旧记忆；
- 第二、三回合：根据前序选择逐步逼近一千字；
- 第四回合：最短路线也会达到 1001 字，必须第一次修改旧记忆；
- 旧记忆从完整版本压缩后不能恢复成完整版本，但本轮封存前可以撤销全部修改；
- 被删除的记忆继续显示为「本轮拟删除」，让玩家在封存前看见自己正在失去什么；
- 封存后先呈现人物反应，再显示可回溯到具体碑文的记忆回声；
- 本轮若改写旧记忆，反馈页默认展开其版本变化和具体损失；
- 总结页显示五次回声、现存村志和碑外残响，不使用善恶评分。

## 视觉系统

视觉基线取自旧版原型，但重新组织了页面层级和响应式布局。

- 墨黑：背景与祠堂暗部；
- 石灰：千字碑与编辑器主体；
- 旧纸：证词、规则和封存反馈；
- 朱砂：主要操作、封印和教学编号；
- 暗金：容量、年代和重要提示；
- 字体：宋体负责正文，楷体负责标题和碑文。

## 中文显示边界

- 玩家可见标题、状态、按钮、角色、版本、后果和总结全部配置中文显示名称；
- 程序内部事件、记忆和页面状态可以使用英文标识符；
- 前端不直接显示内部标识符；
- 浏览器验收未发现英文单词或指定内部状态名泄露。

## 本地打开

在 `designs` 目录启动本地网页服务：

```powershell
python -m http.server 4311
```

打开：

```text
http://127.0.0.1:4311/千字村入口体验原型二/千字村入口体验.html
```

不能直接双击以本地文件方式打开，因为记忆卡需要通过网页服务读取。
